# {{ project_name }}

Минимальный Python-проект: uv, ruff, pre-commit-хуки и типизированная YAML-конфигурация, без фреймворка.

Подходит для прототипов и воспроизведения результатов статей: инфраструктура
уже настроена, а код предметной области добавляется в `src/{{ project_slug }}/`
по мере надобности.

## Быстрый старт

```bash
git init
make init
make config
# Впишите в config.yaml секреты и обязательные поля, если они есть
make run
```

`make init` устанавливает зависимости, собирает шаблон и схему конфигурации и
включает pre-commit-хуки. Если каталог ещё не является git-репозиторием, установка
хуков пропускается с подсказкой: выполните `git init`, затем `make hooks`.

## Конфигурация

Настройки описываются Pydantic-моделями в `settings/` и читаются из
`config.yaml`. `.env` и переменные окружения не используются: вложенность
остаётся обычной YAML-вложенностью, а неизвестный ключ — ошибка при загрузке.

- `Config` в `settings/config.py` — мастер-модель. Новая область настроек —
  новый модуль в `settings/sections/` и поле в `Config`.
- `config.template.yaml` коммитится и описывает полное дерево настроек со
  значениями по умолчанию. Рядом пишется `config.schema.json`: по ней редактор с
  расширением [YAML](https://marketplace.visualstudio.com/items?itemName=redhat.vscode-yaml)
  подсвечивает опечатки и дополняет поля. Оба файла пересобирает pre-commit-хук
  `config-artifacts` (вручную — `make config-template`); `make config-check`
  только сверяет.
- `config.yaml` локальный, содержит секреты и игнорируется Git. `make config`
  создаёт его минимальным: только секреты и обязательные поля, остальное берётся
  из умолчаний моделей. Поэтому в файле видно только то, что задано осознанно, а
  новые умолчания подхватываются без его правки. Нужное поле дописывается по
  шаблону или автодополнению схемы; полная копия шаблона —
  `cp config.template.yaml config.yaml`. Существующий `config.yaml` команда не
  перезаписывает.

Поле, без корректного значения которого проект работать не будет (ключ, адрес
внешней системы), объявляется через `must_be_filled`:

```python
api_key: SecretStr = must_be_filled(
    SecretStr(""),
    "ключ провайдера модели; без него эксперимент не запустится",
)
```

Такое поле, как и поле без значения по умолчанию, попадает в минимальный
`config.yaml` плейсхолдером `<имя_поля>`. Пустое значение и плейсхолдер проходят
валидацию типов, поэтому проверяются отдельно — при загрузке конфигурации, все
разом: `make run` печатает, какое поле не заполнено и зачем оно, и выходит с
кодом 1 без traceback.

## Структура

```text
src/{{ project_slug }}/
├── main.py                точка входа: make run
└── settings/
    ├── config.py          мастер-конфиг: единственный публичный модуль пакета
    ├── sections/          разделы конфигурации, по файлу на раздел
    ├── requirements/      проверка обязательных полей
    └── artifacts/         генерация config.template.yaml, config.schema.json
                           и минимального config.yaml
scripts/                   вспомогательные скрипты разработки
tests/
```

## Коммиты

Сообщения коммитов — в формате [Conventional Commits](https://www.conventionalcommits.org/ru/):
`feat(scope): …`, `fix: …`, `refactor: …`. Хук `commit-msg` только подсказывает
формат и коммит не блокирует: срочный коммит важнее идеального сообщения, поправить
его можно через `git commit --amend`.

Второй хук считает файлы одного расширения в директориях, которых коснулся
коммит, и предупреждает, если их больше пяти: обычно это значит, что часть
файлов об одном и просится в поддиректорию со своим именем. Порог — эвристика,
а не правило, поэтому хук тоже не блокирует коммит; изменить порог можно в
`.pre-commit-config.yaml` (`--max`).
