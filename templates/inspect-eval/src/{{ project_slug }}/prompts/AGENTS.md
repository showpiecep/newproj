# Промпты

## Промпты и KV-cache

- При работе с LLM проектировать промпты с учётом высокого KV-cache hit rate, чтобы
  уменьшать задержку и стоимость запросов.
- Общие системные инструкции, схемы инструментов и другой неизменяемый контекст
  размещать в стабильном префиксе промпта.
- Динамические данные, результаты поиска, временные метки и идентификаторы запросов
  размещать после стабильного префикса.
- Не менять без необходимости формулировки, порядок блоков, пробелы и сериализацию
  общего префикса между однотипными запросами.
- Использовать детерминированную сериализацию структурированных данных: сохранять
  порядок полей и избегать случайного переупорядочивания элементов.
- Переиспользовать общие версии промптов вместо создания почти одинаковых вариантов.

## Организация промптов и структурированные ответы

- Все промпты хранить отдельно от Python-кода в этом пакете; не размещать
  многострочные промпты непосредственно в исходном коде.
- Каждый промпт хранить в отдельном шаблоне Jinja с расширением `.jinja`, по
  тематическим директориям и версиям: `prompts/<область>/<версия>/system.jinja` и
  `user.jinja`. Версия промпта выбирается в конфигурации прогона, поэтому изменение
  текста промпта видно в истории отдельно от изменений кода.
- Динамические значения передавать в промпты через явно названные переменные Jinja.
  Не переносить в шаблоны бизнес-логику и сложные вычисления.
- Если модель должна вернуть JSON, по умолчанию не использовать Structured Outputs и
  JSON Schema response format: они могут ухудшать качество ответа и поддерживаются не
  всеми провайдерами.
- Требуемую структуру JSON явно описывать в инструкции промпта: перечислять поля,
  допустимые значения и требовать вернуть только JSON без Markdown и текста вокруг.
- Ответ модели сначала разбирать через `json.loads`. Если JSON синтаксически повреждён,
  использовать `json_repair.repair_json` как fallback, после чего обязательно
  валидировать объект Pydantic-моделью.
- Не считать успешное исправление через `json_repair` подтверждением смысловой
  корректности ответа: ошибки обязательных полей, типов и допустимых значений
  обрабатывать явно.
