# Deploy

Здесь хранятся файлы развёртывания приложения: контейнеризация, манифесты
оркестратора и конфигурация конкретных сред.

## Декларативное управление

По возможности управление развёртываниями должно быть декларативным и выполняться
из YAML-манифеста. Каждый описанный в нём экземпляр приложения должен явно
указывать:

- уникальное имя развёртывания;
- Git-коммит, из которого собирается приложение;
- путь к отдельному `config.yaml`, предназначенному именно для этого
  развёртывания.

Пример общей структуры:

```yaml
deployments:
  - name: production
    commit: 0123456789abcdef
    config_file: deploy/configs/production/config.yaml

  - name: candidate
    commit: fedcba9876543210
    config_file: deploy/configs/candidate/config.yaml
```

Пути в манифесте следует задавать относительно корня репозитория. Перед изменением
окружения инструмент развёртывания должен проверить структуру YAML, уникальность
имён, существование указанных коммитов и наличие соответствующих конфигурационных
файлов. Желательно поддерживать режим проверки без фактического запуска.

Такой подход позволяет воспроизводимо поднимать одну или несколько версий
приложения, не смешивая версию исходного кода с настройками конкретного окружения.

В эту директорию нельзя добавлять реальные секреты. Секретные значения должны
передаваться выбранным механизмом среды выполнения, например через смонтированный
`config.yaml`. В Git можно хранить безопасные шаблоны конфигурации, но конкретные
конфиги развёртываний с секретами должны быть исключены из отслеживания.
